# Safa Foods Subscription Backend Logic

## 1. Subscription Goal

Subscriptions should convert repeat local buyers into predictable recurring customers.

The first products suitable for subscription are:

- Premium Ginger Garlic Paste
- Fresh Garlic Paste
- Green Chilli Paste

Homemade food items should not be subscription-enabled by default in MVP because availability may vary.

## 2. Recommended MVP Subscription Model

Keep the first version simple.

Do not start with fully custom schedules for every customer.

### MVP subscription plans

- Weekly plan
- Monthly plan

### Recommended delivery frequency options

- `weekly_once`
- `weekly_twice`
- `monthly_four`

Meaning:

- `weekly_once` = 1 delivery every week
- `weekly_twice` = 2 deliveries every week
- `monthly_four` = 4 scheduled deliveries in a month

Do not start with daily or alternate-day subscriptions in MVP. That creates too much operational complexity.

## 3. Subscription Purchase Flow

### Step 1: User account

User must create an account before buying a subscription.

Required user fields:

- full name
- phone number
- email
- password or OTP login
- delivery address

### Step 2: Product selection

User opens a product page and sees:

- one-time price
- subscription price
- savings amount or percentage
- delivery frequency options
- next available delivery date
- billing period
- included quantity

### Step 3: Plan selection

User selects:

- product
- quantity per delivery
- frequency
- start date
- address

### Step 4: Pricing summary

Checkout should show:

- product subtotal for plan
- plan discount or savings
- delivery fee rule
- total payable now
- next billing date
- next delivery date

### Step 5: Payment

Subscription payment is prepaid only through Razorpay.

COD is not allowed for subscriptions.

### Step 6: Activation

After successful payment:

- subscription becomes `active`
- backend creates future delivery schedule
- customer receives confirmation

## 4. Recommended Pricing Logic

There are two valid approaches.

### Option A: Delivery fee included in plan

Example:

- plan price already includes delivery for all scheduled drops

Benefits:

- easier customer understanding
- easier marketing
- better checkout conversion

### Option B: Delivery fee calculated separately

Example:

- plan subtotal + delivery fees for scheduled drops

Benefits:

- more precise margin control

For Safa Foods MVP, choose **Option A** if possible.

Reason:

- simpler for customers
- easier to market on homepage and product pages
- easier for WhatsApp sales conversations

## 5. Recommended Subscription Pricing Structure

Example model:

- One-time jar price: `Rs. 99`
- Weekly subscription effective price: `Rs. 94`
- Monthly subscription effective price: `Rs. 89`

Display this as:

- `Subscribe and save`
- `Save 5% weekly`
- `Save 8% monthly`

Exact numbers should be finalized with margins later.

## 6. Subscription Status Model

Each subscription should have one of these statuses:

- `draft`
- `pending_payment`
- `active`
- `paused`
- `cancelled`
- `expired`

Meaning:

- `draft` = configuration started but not purchased
- `pending_payment` = payment not complete
- `active` = running normally
- `paused` = temporarily stopped
- `cancelled` = terminated by user or admin
- `expired` = plan completed

## 7. Delivery Schedule Logic

Each active subscription should create scheduled deliveries.

Each scheduled delivery should store:

- subscription id
- user id
- product id
- quantity
- scheduled date
- delivery address
- zone
- delivery fee
- order status

### Recommended scheduling behavior

- schedule is created at the time of subscription activation
- next 4 to 8 deliveries can be pre-generated
- additional future deliveries can be generated by a cron job

## 8. Billing Logic

### MVP recommendation

Do not start with automatic recurring card charging if it complicates implementation.

Safer MVP:

- customer prepays for a weekly or monthly plan
- subscription covers a fixed number of deliveries
- when plan ends, prompt renewal

This is operationally much simpler than full recurring billing.

### Future version

Later you can add:

- Razorpay recurring autopay
- card / UPI mandate support
- automatic renewal reminders

## 9. Pause / Resume Rules

Recommended MVP rules:

- customer can pause subscription from account or via admin
- pause must happen at least `1 day` before next scheduled delivery
- paused subscription does not generate active fulfillment orders
- resume creates the next available delivery schedule

## 10. Cancellation Rules

Recommended MVP rules:

- cancellation allowed only before next fulfillment is locked
- if payment covered multiple future deliveries, refund policy must be explicit

Suggested business rule:

- cancel before next scheduled prep window
- unused deliveries can be converted to wallet credit or partial refund

Exact refund policy must be added to Terms and Subscription Policy.

## 11. Missed / Failed Delivery Rules

Backend should support:

- `delivery_failed`
- `customer_unavailable`
- `rescheduled`
- `skipped`

Recommended MVP behavior:

- operator can mark a scheduled delivery as failed or skipped
- one manual reschedule allowed
- repeated failures trigger admin review

## 12. Admin Controls

Admin panel must support:

- create subscription-enabled products
- enable or disable plan types per product
- set discount percentages
- set delivery windows
- view active subscriptions
- pause or cancel subscriptions
- reschedule a delivery
- mark delivery completed
- send renewal reminders

## 13. Customer Account Requirements

Customer account must show:

- active subscriptions
- next delivery date
- selected product
- quantity
- billing / plan period
- savings
- subscription status
- pause button
- cancel button
- address update option
- order history

## 14. Notifications

Customer should receive notifications for:

- subscription activated
- upcoming delivery reminder
- out for delivery
- delivered
- paused
- renewal due

Recommended channels:

- WhatsApp first
- email second

## 16. Recommended MVP Subscription Rules

Use these exact MVP rules:

- only selected paste products are subscription-enabled
- subscriptions require account creation
- subscriptions are prepaid only
- no COD for subscriptions
- fixed plans only: weekly once, weekly twice, monthly four
- fixed-cycle payment, not full autopay in MVP
- customer can pause or resume
- customer can cancel subject to policy
- renewal happens manually at first

## 17. Final Recommendation

For Safa Foods MVP, subscription logic should be **predictable and operationally simple**, not overly flexible.

That means:

- fixed plan options
- prepaid plans
- visible savings
- clear schedule
- simple pause and renewal flow

This is the best way to launch a reliable subscription business without breaking operations.
